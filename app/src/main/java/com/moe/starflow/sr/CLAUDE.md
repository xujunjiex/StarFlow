# 图片超分模块

> 范围：本文记录 `sr/` 的当前实现约束。跨模块规则见仓库根目录 `AGENTS.md` 和 `CLAUDE.md`。源码与测试为准；实现变化后同步更新本文。

## 产品路径

当前 11 个 2x 模型来自 downloadinfo.json；使用 ncnn。唯一页执行入口是 ReaderTranslationController.runSr → SrProcessor → NcnnSrEngine → JNI。Anime4K 是独立的 GLES3 阅读器显示处理，保留原有着色器与线程归属，不能当作模型超分成功结果。OCR 的 ONNX 依赖仍需保留。

- 不使用邻页预加载、宽高跳过阈值、1080 短边限制、输出 10MP / 输入 2.5MP 隐藏上限。
- 仅按用户 MP 阈值预处理，默认 1.5MP。输入 ≤ 阈值原图送模型；超过则 k=sqrt(阈值像素/原像素)，宽高向下取整。0 不主动压缩。
- 分步减半再用 Canvas 双线性过滤到目标，处理在内存中，不重新编码原文件。下采样会丢失信息，不要宣称无损。
- 输出必须符合实际送入尺寸×模型倍率；产物比原图小也保存。只有内存和可寻址缓冲区的实际限制；失败不自动改参数重试。

## 模型与后端

下载固定提交版本，文件大小及 MD5 校验后可用。SE/Pro syncgap=3，Nose=0；输入极小时 SE/Pro 使用完整 SE 统计，避免采样为空。Waifu2x 用有效卷积补边；通用五模型用真实邻域 halo + 模型自身 same padding，严格校验输出大小、通道和有限值，按模型清单处理 RGB/BGR。

无 Vulkan 时 Waifu2x、CUGAN 和通用模型使用 CPU，ESRGAN 明确报不可用。CPU 使用 ncnn simpleomp 与线程数，诊断显示实际后端。存储精度与 FP16 算术分别控制；FP32 关闭 FP16 packed/storage/arithmetic。GPU 不支持的精度回落必须反映在记录里。shader SPIRV 不能跨精度复用。

分块 0 为自动选择；其他值直接用于 tile 核心区域。性能档为分块间等待 0/5/15ms，不表示吞吐百分比，单块不会额外等待。CUGAN 统计阶段可能增加工作块；不要把工作块数理解成最终输出的网格数。

## 生命周期

OCR 优先占 OcrLock；推理与模型加载期间保持独立心跳。取消停在下一个原生分块边界：原生尚未退出时保持锁和“正在停止”，不提交该页新结果，已完成页保留。原生 shared_ptr 注册表 + Kotlin lease 保护模型生命周期；切换模型不能释放在用实例。失败记录具体阶段；推理中间张量内存不足建议减小 tile，整图/RGB/输出分配不足建议减小 MP。

页面任务在开始解码前捕获该页 generation，并将其传到解码失败记录、推理与保存阶段。注册任务和提交产物前都重新核对 generation；删除页会先递增 generation 再取消任务。不能让删除前开始的迟到任务采用新 generation，否则旧结果可能复活。

SrRequest 冻结任务参数和模型权重版本。参数变化保留旧产物并标记旧配置。整章任务遇到异模型或旧配置时确认：跳过所有可用产物、全部重做、取消。逐页失败继续下一页，公共模型预检失败整章不启动。

## 保存与显示

活动产物位于当前 `.starflow/books/<UUID>/sr/`；阅读器入口要求书目已有书库 UUID，调用捕获 `LibrarySession` 和作品引用，清理只作用于当前目录。基准广播仅在 debug 包启用，基准输入与日志位于 `files/sr/` 下。旧位置的基准输入与日志首次访问时迁入该目录。

SrStore 使用书籍身份 + 稳定源页键，每页保留一个有效超分结果；图片使用不可变 UUID 修订，新图写入并验证后才提交新的不可变 JSON 修订引用，再删除旧图；SAF 不依赖原子重命名，失败保留旧图。产物没有容量上限，不按使用时间自动淘汰；仅清理无引用图片和中断写入的临时文件。删除增加页 generation 并取消任务，迟到输出不能恢复已删除结果；有效性检查与数据库过程记录独立。

紫色进度条以实际可用产物为准，与 OCR/翻译成功无关。缺失/损坏文件显示结果已丢失。保存、删除刷新记录和底图；渲染缓存签名含真实产物修订，渲染中签名变化丢弃结果。预览不得回收缓存自持的 bitmap。

全局历史数据库保留旧 schema v24，活动书库使用按目录分离的 `LibraryDatabase` v1：v21→22 增加小说 imagePayload；v22→23 增加 SR sourcePageKey/executionJson；v23→24 兼容性补列。两表页序重排使用同一个 Room 事务。记录包含请求与有效参数、尺寸、MP、后端、解码/等待/初始化/预处理/RGB/推理/保存/总耗时。修改状态字面量须同步 DAO 查询。
