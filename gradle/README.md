# 按需验证

本目录维护 Gradle 验证入口与旧源码守卫清单。目标是只编译、运行能回答当前问题的测试，不把全套检查作为日常工作步骤。

## 入口

从仓库根目录调用 Gradle Wrapper，保留默认 daemon 和缓存。

| 任务 | 范围 |
|---|---|
| `:app:verificationPlan -PtestClasses=完整类名` | 输出选集并核对实际 Kotlin 编译输入，不编译、不执行测试 |
| `:app:testFocused -PtestClasses=完整类名` | 只编译指定行为测试与共享夹具，再运行指定类 |
| `:app:testDebugUnitTest` | 既有调试单元测试入口，默认排除纯源码文本守卫 |
| `:app:testSourceGuards` | 显式运行 `gradle/source-guards.txt` 中的旧源码守卫 |
| `:app:testAllUnit` | 显式运行全部调试单元测试，包含旧源码守卫 |

完整测试套件仅在用户明确要求时运行。多个类名使用逗号分隔；不支持包或方法通配符。日常优先选择 1–3 个直接覆盖失败场景的行为测试，不按消费模块的数量扩展到整个包。用户要求不测试时不运行测试或 lint；需要 APK 时单独打包。

## 编译裁剪

`gradle/verification.gradle` 在配置阶段将未选中的测试源文件同时排除出 Kotlin 编译、kapt stubs 和 Java 编译。JUnit 的运行过滤单独保留，避免历史编译输出混入本次运行。正式应用代码仍按正常依赖编译。

测试文件采用 `*Test.kt`、`*Tests.kt` 或对应 Java 命名，文件名与顶层类名一致；共享夹具使用独立文件，不使用这些后缀。测试之间不要继承或引用其他测试类的私有实现；共用逻辑放在夹具中，否则单独编译该测试时应当失败并修正依赖，不自动扩大运行范围。

选择不同测试类会改变增量编译输入，因此应一次确定小选集，避免在多个选集之间反复切换。该入口不保证固定耗时，也不能省略首次应用编译或依赖准备。

## 源码守卫

清单仅收录已确认通过读取源码并匹配字符串、正则或位置来检查实现的测试。保留原文件与断言，方便确有接线审查需要时显式运行；不按文件名猜测，也不排除调用实际产品逻辑的混合测试。

新增回归应验证输入、输出、错误、取消与资源生命周期。只有字符串出现不能证明功能正确；参数改名或空格变化也不应成为产品故障。真实 ONNX、llama.cpp、Vulkan 和视觉效果需相应运行环境，不能以 JVM 模拟结果替代。

## 失败处理

只检查当前命令生成的结果；旧报告不是本轮结论。断言失败先区分产品行为、测试夹具、环境与过时源码匹配；不自动运行更大范围、完整 lint 或设备测试。连接设备的操作继续使用仓库既有授权与安全安装流程。
